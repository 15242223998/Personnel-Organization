# 辽宁某某大学 · 高校干部人事组织管理系统

面向**辽宁某某大学**组织人事工作的高校干部人事组织管理系统，依据学校“**十四五**”规划提出的治理体系和治理能力现代化建设要求，以干部人事档案数据为底座，服务高素质专业化干部队伍建设。

系统涵盖干部信息管理、组织机构、选拔任免、职级晋升、调配管理、年度考核、民主测评与平板评审投票（含签字留证）、监督管理、日常事务、统计分析等核心模块，覆盖“选、育、管、用”全链条，采用政务蓝风格界面，与学校智慧校园建设整体规划相衔接。

## 建设背景

- 紧扣**辽宁某某大学“十四五”规划**中关于深化内部治理、推进管理数字化转型的目标，把组织人事工作纳入学校智慧校园“一张网、一平台、一门户”建设框架。
- 面向“十四五”干部队伍建设需要，落实党管干部原则，实现干部档案电子化、任免流程规范化、考核监督全程留痕，为学校党委科学选人用人提供数据支撑。
- 以“数据一个库、业务一条链、审批一个口”为建设方向，逐步实现组织机构、干部档案、任免调配、考核监督等业务协同联动。

## 功能模块

### 干部管理
- **干部信息管理** — 干部档案的增删改查、批量导入导出、排序筛选、在职/离退休/调出/辞职分库
- **后备干部库** — 后备干部入库（仅限在职干部）、培养跟踪、出库管理

### 组织机构
- **组织机构管理** — 机构树形管理、编制数/实有人数维护（实有人数按在职工级干部实时统计）
- **班子管理** — 机构班子成员（党委书记/院长/副院长等）登记、维护与任职起止
- **职务层次管理** — 职务层次的增删改查
- **职级管理** — 职级类型的统一管理（晋升记录自动联动干部当前职级）

### 干部业务
- **干部任免管理** — 全流程管理（动议 → 民主推荐 → 考察 → 讨论决定 → 公示 → 任职），任职备案自动回写干部档案现任信息；启动任免时校验近三年年度考核达标
- **干部调配管理** — 干部调动/转任记录管理，自动同步档案状态（在职/离退/调出），记录修改/删除后按剩余记录重算档案状态
- **职级晋升管理** — 职级晋升记录管理，自动同步干部职级；晋升资格判定接入近三年考核核验
- **干部考察登记** — 任前/年度/专项/换届考察记录登记管理
- **政策法规管理** — 党内法规/干部选拔/干部监督等政策文件台账（标题/文号/正文/附件）
- **干部自助申报（档案更正闭环）** — 干部可提交"档案信息更正"（电话/邮箱/学历/政治面貌等 6 类白名单字段，自动抓取当前值作对比），审批通过后由系统自动回写干部档案并通知申报人

### 监督考核
- **干部考核管理** — 年度考核（优秀/称职等次，自动回写档案考核记录）、考核方案、德能勤绩廉维度/指标模板、民主测评
- **平板评审投票** — 面向局域网平板现场评审：评分式（按指标打分）与表决式（赞成/反对/弃权）两种投票、评审材料审阅、手写签字留证（签字图像+MD5+设备IP+时间留痕）、票决结果与签字记录查询；平板端访问 `/tablet`
- **干部监督管理** — 廉政意见、信访举报、个人事项报告、提醒函询诫勉、经济责任审计、人员预警
- **预警规则与生成** — 预警规则管理（红/橙/黄分级、触发阈值）；一键"按规则生成预警"扫描真实台账（证件到期/出国超期/休假超时/班子任职超期/到龄退休）自动产生分级预警；普通干部在首页/消息通知仅看到本人相关预警

### 日常事务
- 证照管理、出境记录、休假管理、教育培训、挂职锻炼（均含业务规范校验与台账），以及请假/培训/出国(境)等干部自助申报（按 `sys_user.cadre_id` 归属档案，审批结果通知申报人）

### 统计分析
- 年龄/性别/学历/政治面貌/职务层次图表分析（ECharts）
- 机构干部统计表

### 系统管理
- 用户管理、注册审批、权限授予（按账号模块授权）、字典管理（国标）、操作日志/登录日志、数据权限

## 认证与安全（已启用）

- 登录成功签发 JWT（HS256，默认有效期 24 小时），前端 `Authorization: Bearer <token>` 携带
- Spring Security 统一鉴权：登录/注册/接口文档及数据库连接探测只读接口（`/api/db/probe`、`/api/db/current`）外，其余接口须携带有效令牌，未登录返回 401、越权返回 403（JSON）；`/api/db/align`、`/api/db/switch` 等变更性接口强制系统管理员（userType=1）
- 登录失败节流：同一账号连续输错 5 次，15 分钟内即使密码正确也拒绝（计数存 Redis，无 Redis 自动落内存）
- 模块权限（菜单访问控制）：生效权限 = 系统管理员（用户类型 1）全通 → 用户已单独授权（"权限授予"勾选）优先 → 否则回退该账号"用户类型"的内置默认模板（2~4 校级领导/组织部部长/组织员=9 个业务模块，5 二级学院领导=6 个模块，6 普通干部=默认空、需管理员单独授权）。模块菜单全员可见，未授权账号进入页面时被拦截提示（原 `sys_role` 角色层已不再参与权限计算）
- 数据权限：按用户类型自动过滤（1~4 全量 / 5 本级及下级 / 6 本部门），干部档案分页/详情/导出实时生效
- 干部状态、调配/任免/晋升均与干部档案联动，保证档案"现任职务/部门/职级/状态"一致；年度考核结果回写档案，并作为晋升资格判定与任免启动的前置核验
- 消息通知（铃铛）：管理职能账号收到管理类聚合通知（测评/请假/证照/出境/注册审批/预警），普通干部仅收到本人相关预警与本人申报/休假审批结果

> 初始账号：`admin / 123456`（系统管理员，数据全量可见）

## 数据库热切换与自动对齐（运行期特性）

登录页左下角 **"连接到服务器"** 支持在同一前端下连接不同的 MySQL 后端库，全程免重启：

- **填连接**：主机 / 端口(3306) / 数据库(默认 `POP`) / 账号 / 密码（默认显示 `localhost:3306/POP`、`root/666666`）
- **探测三种结果**：
  1. 库存在且结构一致 → 直接"连接"切换；
  2. 库存在但缺表 → 弹窗展示**差异清单（缺表名）**，可 [仍连接]（不改数据）或 [取消]；
  3. **库不存在** → 弹窗"数据库出错，是否进行数据对齐"并列出**即将创建的 51 张表**；点 [确认对齐] 才在目标实例上 `CREATE DATABASE` + 按 `sql/init.sql` 整份重建（DROP+建表+种子），完成后自动切换；点 [取消，只登录前端系统] 则不切换、按当前库登录
- **防误操作**：探测到目标库已有项目表时对齐接口拒绝执行（`库已存在项目表`），不会清掉有数据的库；切换前强制试连，失败自动保留原库
- **记忆与恢复**：切换成功后连接写入 `personnel-backend/run/db-conn.json`（已 gitignore），后端重启自动连回上次选择；删除该文件即回默认 `master/POP`
- 技术说明：基于 baomidou `dynamic-datasource` 路由数据源（`spring.datasource.dynamic.*`），切换对 MyBatis/MyBatis-Plus 透明；同弹窗另保留"API 服务器"页签可切换前端后端地址
- **换机器部署注意**：`application.yml` 属本机环境配置（未纳入 git），新环境需把 `spring.datasource.*` 迁移为 `spring.datasource.dynamic.datasource.master.*` 形式；执行对齐的 MySQL 账号需具备 `CREATE DATABASE`/建表权限

## 快速开始

### 环境要求
- JDK 17+
- Maven 3.8+（若未安装，项目内置便携版于 `.tools-maven`，启动脚本会自动探测）
- Node.js 18+
- MySQL 8.0+
- Redis 7.0+（可选，当前代码未实际使用）

### 一键启动（推荐）

Windows 下直接双击项目根目录的 `启动系统.bat`：
1. 自动探测 JDK 17 与 Maven
2. 启动后端（`mvn spring-boot:run`，端口 8080）
3. 启动前端（`npm run dev`，端口 5173）
4. 自动打开浏览器 http://localhost:5173

也可以分别双击 `personnel-backend/启动后端.cmd` 或手动运行：

```bash
# 1. 初始化数据库（先按需修改 application.yml 中数据源）
#    默认：jdbc:mysql://localhost:3306/POP，root / 666666
mysql -uroot -p666666 < sql/init.sql

# 1.1 可选：灌入演示数据（机构/编制/干部档案 + 考核/日常事务/平板评审示例）
mysql -uroot -p666666 POP < sql/seed-demo.sql

# 2. 后端
cd personnel-backend
mvn spring-boot:run        # http://localhost:8080，API文档 /doc.html

# 3. 前端
cd personnel-frontend
npm install
npm run dev                # http://localhost:5173（已代理 /api 到 8080）
```

> 演示账号（`seed-demo.sql` 提供，密码均 `123456`）：
> - `admin`：系统管理员（全量数据）
> - `caohaoran`：组织部部长（已绑定干部档案）
> - `qinxia`：普通干部（已绑定干部档案，可在平板自助申报/参与投票）

### 构建部署

```bash
cd personnel-frontend
npm run build
```

构建产物在 `dist/` 目录，可直接部署到 Nginx 等 Web 服务器。

#### 局域网平板评审部署（Nginx 示例）

项目提供 `deploy/nginx-lan.conf`，将前端 `dist` 与后端 `/api` 同源反代后即可供局域网平板访问：

```bash
# 前端已构建出 dist 后
# 1) 按实际路径修改 deploy/nginx-lan.conf 中的 root 指向 dist
# 2) 后端运行在 127.0.0.1:8080（已由 nginx 反代 /api）
# 3) 启动 nginx（Windows 双击/命令；Linux: nginx -c .../nginx-lan.conf）
```

- 桌面后台：`http://<主机局域网IP>/`
- 平板投票页：`http://<主机局域网IP>/tablet`
- 若仅临时体验，前端可用 `npm run dev -- --host`，平板访问 `http://<主机IP>:5173/tablet`（注意放行防火墙）

## 说明与已知事项

- 业务页面均对接后端 `/api/**` 真实接口（登录认证、操作/登录日志、注册审批、统计分析、干部信息主链路（在册/后备/档案）、组织/班子/职务层次/职级、任免全流程、调配晋升、年度考核+民主测评+平板评审投票+签字留证、日常事务（证照/出境/休假/培训/挂职/自助申报）、监督管理（廉政/信访/个人事项/函询诫勉/经济审计/预警）、政策法规、干部考察登记、字典管理、预警规则管理、权限授予、用户管理（含用户↔档案绑定））；前端不再保留静态演示数据，数据库无对应记录时页面展示真实空态。
- 权限模型已收敛：原"角色管理"入口已移除（`sys_role` 不再参与权限/数据范围计算），改为"用户类型内置模板 + 权限授予页按账号单独授权/恢复默认"；模块菜单全员可见、未授权进入页面即拦截提示。
- 预警使用方式：管理端"监督管理 → 预警规则管理"维护规则 → 智能预警页点"按规则生成预警"扫描真实台账产出分级预警（红/橙/黄/蓝），可重复执行且幂等。
- 演示数据：执行 `sql/seed-demo.sql` 可重复灌入机构（27 个）、编制与干部档案（约 470 人），以及年度考核、测评方案（评分式/表决式）、预警规则与按规则生成的预警、证照/出境/休假/培训/挂职/自助申报、班子、政策法规、函询诫勉、经济责任审计等示例记录。数据中姓名随机虚构、职务为通用占位，不含真实人员信息，便于演示与联调。
- 平板评审投票：进行中方案会出现在 `/tablet` 平板端；投票完成后需手写签字留证（图像与 MD5/设备 IP 存档于 `assessment_signature`），签字后不可再改票；管理端可在方案行"更多 → 签字留证 / 测评对象与材料"中查看留证与维护评审材料。
- 干部自助申报归属：`sys_user.cadre_id` 绑定后，申报方可归属到具体干部档案；绑定操作在"系统管理 → 用户管理 → 绑定档案"。
- 干部档案等数据会按"数据权限"过滤；以 `admin/123456` 登录可查看全量数据。
- `.tools-maven/` 为 Maven 便携版（启动脚本依赖，正式安装 Maven 后可删除）。
